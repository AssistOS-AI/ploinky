Services

The services that turn a workspace request into a running, routed, and supervised agent.

Ploinky keeps each responsibility narrow. Workspace and repository services decide what is available. The lifecycle service prepares a verified agent instance. A selected runtime runs it in isolation. The Router exposes only admitted routes, while WebChat provides the browser interaction surface. Security and supervision services apply across that flow.

Workspace state

The workspace service owns the persistent Ploinky state for one workspace. It records enabled agents and the selected workspace configuration, so lifecycle commands act on a known instance rather than on a similarly named process.

Main operationWhat it does
Read enabled agentsLoads the agent registry and rejects an unreadable or corrupt registry instead of using partial state.
Save a registry changeWrites the replacement registry atomically and makes a previously active route generation ineligible until routing has been reconciled.
Store workspace settingsPersists the static-agent selection and other workspace-level settings without treating those settings as a route authorization update.

Repositories and manifests

The repository service makes agent and skill sources available to a workspace. It remembers a repository's source and branch selection, distinguishes installed repositories from the active set, and uses each agent's manifest as the input to later lifecycle work.

Main operationWhat it does
Add or install a repositoryResolves a configured or supplied source, obtains the checkout, and records the source details needed to find it again.
Enable or disable a repositoryControls whether its agents and skills participate in ordinary discovery while leaving repository management explicit.
Refresh a repositoryUpdates an existing Git checkout using the configured branch policy and preserves the recorded source metadata.
Read manifest dependenciesCollects repository and agent requirements declared by a manifest before runtime startup begins.

Agent lifecycle

The lifecycle service converts an agent reference into one exact enabled instance. It resolves repository-qualified names and aliases, builds the dependency graph, validates runtime policy, and coordinates the registry with routing. This is why enable agent starts an agent rather than merely adding a record.

Main operationWhat it does
Prepare startupResolves the selected profile and dependency graph, rejects cycles and invalid policies, creates the instance work area, and reserves a new identity and enable generation.
Enable an agentCreates or replaces the exact runtime, waits for readiness, then publishes its route together with the ready registry record.
Start a workspaceStarts the static agent and dependency graph in dependency order, while applying the declared manual-start policy to unrelated enabled agents.
Disable an agentWithdraws the matching route first, stops and removes only the captured runtime, and keeps its persistent data for a later enablement.

Isolated runtimes

The runtime service runs each enabled agent using the permitted platform backend: an OCI container runtime, a Linux Bubblewrap sandbox, or the macOS Seatbelt sandbox. It applies the manifest and profile while preserving Ploinky's isolation and networking rules.

Main operationWhat it does
Choose and admit a runtimeChecks that the requested backend, network mode, mounts, and resources satisfy the workspace runtime policy before launch.
Build the process environmentCombines permitted manifest values with runtime-owned workspace, identity, MCP, and Router values; reserved names cannot be replaced by a manifest.
Mount working dataProvides the source, persistent agent home, shared workspace data, Agent library, and prepared dependencies according to the selected enable mode.
Verify readinessUses the manifest's readiness contract before a runtime becomes routable, and removes failed candidates from the startup path.

Router

The Router is Ploinky's single in-Box HTTP, streaming, and WebSocket entry point. It exposes the authenticated workspace surface and forwards an admitted request only to the target selected by the active routing generation. Agent listeners remain private to the Box.

Main operationWhat it does
Authenticate and authorizeApplies route access policy, caller rules, and request checks before it resolves an agent route or a Router-owned endpoint.
Proxy an active routeResolves the current generation-bound target, rechecks that the generation remains active, and forwards HTTP, SSE, or WebSocket traffic.
Serve MCP accessConnects users and authorized agents to routed MCP services, minting request-bound invocation material for delegated calls.
Serve workspace surfacesHosts WebChat, status, uploads, blobs, workspace-file operations, authentication, and administration endpoints under the same access boundary.

WebChat

WebChat is the browser interaction service served through the Router. An authenticated user can choose an enabled agent, open a terminal-backed session, send input and control actions, answer interaction prompts, follow tasks, and work with approved workspace files and uploads.

Main operationWhat it does
Resolve the target agentAccepts a selected enabled agent only when its command configuration can be resolved for the current workspace.
Manage interactive sessionsCreates and maintains the terminal stream used for CLI input, output, control messages, and interaction requests.
Handle tasks and filesProvides task views, workspace suggestions, controlled directory selection, and upload handling within the authenticated workspace context.

Configuration and identity

The configuration and identity services resolve the values an agent needs without allowing an agent manifest to take ownership of Ploinky-controlled credentials. They combine declared environment requirements, workspace values, profile rules, generated identities, and the active network contract.

Main operationWhat it does
Resolve environment requirementsReads declared values from workspace secrets, process environment, environment files, and manifest defaults, then reports required values that remain unresolved.
Expose a named valueMaps a workspace value to an agent-visible environment name through the manifest's explicit exposure rules.
Inject instance identityAssigns the canonical agent principal, runtime instance, and enable generation used by the Router and runtime to identify the exact caller.
Protect confined runtimesWithholds Router endpoints and reusable request credentials from runtimes that have no permitted network path.

Supervision and recovery

The Watchdog supervises the Router and the managed agent fleet after startup. It checks health through the Router's private health socket, observes runtime state, and handles failure without reviving an instance that the lifecycle service deliberately disabled.

Main operationWhat it does
Check Router healthPeriodically reads the private health result and treats a timeout, malformed response, or unhealthy status as a failure.
Restart with limitsUses exponential backoff and a bounded restart window; repeated Router failures trip a circuit breaker instead of restarting indefinitely.
Monitor managed agentsChecks recorded runtimes and their readiness state so stale or unhealthy routes can be inactivated before recovery work starts.

How services work together

An enablement request follows one controlled path. The workspace services identify the requested agent, lifecycle and runtime services make it ready, and the Router makes the ready agent reachable. Security and supervision apply throughout this flow.
