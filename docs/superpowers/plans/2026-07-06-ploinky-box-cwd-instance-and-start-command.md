# ploinky-box: cwd-Derived Instances + `start` Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When `--name` is omitted, derive the ploinky-box instance name from the current working directory basename (like normal ploinky workspaces), and add a `ploinky-box start <agent> [port]` convenience command that creates/starts the box and runs `ploinky start <agent> 8080` inside it. **No backwards compatibility** (explicit direction, 2026-07-06): the bare shared `ploinky-box` instance is retired outright — every instance name is `ploinky-box-<suffix>`, always.

**Architecture:** All changes live in `container/ploinky-box.mjs` (the single-file Node wrapper) and its test file `container/wrapper-tests.mjs`. Instance identity resolution becomes an explicit, exported, unit-testable step (`sanitizeBoxSuffix` + `resolveInstanceIdentity`) that runs in `main()` after parsing and populates `cfg.name`; `instanceName()` simplifies to always-prefixed. `start` composes the existing `cmdUp` with the existing exec pattern from `cmdRun` plus a router probe reusing `urlOk`/`hostPort`.

**Tech Stack:** Node ≥ 20 ESM, node builtins only (`node:path`, `node:fs`, `node:os`, `node:child_process`, global `fetch`), `node:test` for tests. No npm dependencies anywhere under `container/`.

## 2. Desired behavior and CLI examples

When `--name` is omitted, the instance name is inferred from `path.basename(process.cwd())`, sanitized with the same character class core ploinky uses. There is no way to address a bare `ploinky-box` instance anymore.

```bash
cd ~/work/testExplorerFresh
ploinky-box start explorer
# infers instance testExplorerFresh and creates:
#   container ploinky-box-testExplorerFresh
#   volume    ploinky-box-testExplorerFresh-workspace
#   volume    ploinky-box-testExplorerFresh-containers
# publishes host 127.0.0.1:8080 -> box 8080
# then runs inside the box:  ploinky start explorer 8080
```

```bash
cd ~/work/testExplorer2
ploinky-box --port 8081 start explorer
# infers instance testExplorer2, publishes host 8081 -> box 8080,
# and still runs inside the box:  ploinky start explorer 8080
```

```bash
ploinky-box start explorer 8081     # positional [port] = host port, same as --port 8081
ploinky-box --name qa up            # explicit --name always overrides cwd inference
ploinky-box status                  # status of the current directory's box
ploinky-box destroy                 # destroys the CURRENT DIRECTORY's box (prompt names it)
```

`start <agent> [port]` semantics, precisely:

1. Resolve the instance (inferred or `--name`).
2. Run the existing `up` flow for it (create if missing, start if stopped, no-op if running; image pulled on first use).
3. Exec `ploinky start <agent> 8080` inside the box (in `/workspace`, exactly like `run start <agent> 8080`). Core ploinky auto-enables the agent when it exists in a known repo (`cli/services/workspaceUtil.js:499-503`); if the agent's repo isn't present in the box, the in-box ploinky error is surfaced as-is — the wrapper does not add repos.
4. Probe the router on the actual published host port for up to 30s; print the URL on success, warn + exit 1 on timeout.

The positional `[port]` and `--port` both mean the HOST port (default 8080). The in-box router port is always 8080 (design decision: no override flag — matches the README's "one rule about ports").

## 3. Edge cases and compatibility policy

### 3.1 Compatibility policy: none (by explicit direction)

There is no legacy-access flag, no migration path, and no upgrade guide. Accepted consequences, stated so the implementer knows they are deliberate:

| Consequence | Detail |
| --- | --- |
| Old shared boxes become unaddressable | A pre-existing bare `ploinky-box` container and its `ploinky-box-workspace`/`ploinky-box-containers` volumes can no longer be reached by any wrapper command. Cleanup is manual, engine-level: `podman rm -f ploinky-box && podman volume rm ploinky-box-workspace ploinky-box-containers`. One README line documents this; nothing more. |
| Bare command meaning changes | `ploinky-box up|status|stop|destroy|…` now targets `ploinky-box-<cwd basename>`. The destroy prompt (which names the exact container + volumes) plus the new inferred-name note and nothing-to-destroy guard are kept — not as migration aids, but because inferred targeting makes "destroy in the wrong directory" a permanent footgun worth guarding. |
| `--name default` stays magic-free | It targets `ploinky-box-default`, like any other name. No reserved words anywhere. |
| `instanceName()` loses its bare branch | Always returns `ploinky-box-<name>`; the un-suffixed form is unrepresentable, which is what enforces the policy. |

### 3.2 Inference and sanitization rules (locked)

| Input (cwd basename) | Result | Rule |
| --- | --- | --- |
| `testExplorerFresh` | `ploinky-box-testExplorerFresh` | Case preserved (engine names allow uppercase; matches the requested UX) |
| `my repo!` | `ploinky-box-my_repo_` | Every char outside `[a-zA-Z0-9_.-]` → `_` — same class as `cli/services/docker/common.js:200`; runs are NOT collapsed (parity with core) |
| `.config` | `ploinky-box-.config` | Leading dot fine: the `ploinky-box-` prefix satisfies the engine's `[a-zA-Z0-9]` first-char rule |
| 64+ char basename | suffix truncated to 63 chars | Keeps `<instance>-workspace` comfortably inside engine name limits; truncation collisions are documented, not detected |
| `日本語` (no ASCII alnum at all) | error | Sanitized suffix with no `[a-zA-Z0-9]` is un-inferable → die with `pass --name X` guidance (silent `___` collisions would be worse) |
| cwd = `/` (empty basename) | error | Same die-with-guidance |
| Same basename, different parent dirs | Same instance | Documented caveat: inference keys on the basename only; use `--name` to disambiguate. Corollary: the same directory always maps to the same box. |
| Symlinked cwd | Physical path's basename | `process.cwd()` resolves symlinks; noted in README, no code |
| Explicit `--name` with unsafe chars | Passed through raw, engine rejects | Unchanged: sanitization applies ONLY to inferred names; explicit names are the user's responsibility |

### 3.3 How inferred naming applies to each command (locked)

Identity resolution runs once in `main()` for every command except `help` (`-h`/`--help`/bare usage also skip it, so `ploinky-box help` works from `/`). After resolution, `cfg.name` is populated and **all** commands behave exactly as if that `--name` had been passed:

| Command | With inferred name | Extra behavior added by this plan |
| --- | --- | --- |
| `up` | Creates/starts `ploinky-box-<cwd>` | none |
| `start` | New command; see §2 | new |
| `cli`, `run`, `cp`, `logs` | Exec against `ploinky-box-<cwd>`; `requireRunning` hint shows `--name <resolved>` (copy-pasteable from any directory) | hint text only |
| `status` | Probes `ploinky-box-<cwd>`; when it does not exist AND the name was inferred, the message appends an inferred-name note | note |
| `stop` | Stops `ploinky-box-<cwd>`; same inferred-name note on "does not exist" | note |
| `update` | Recreates `ploinky-box-<cwd>`; resume hint uses `--name <resolved>` | hint text only |
| `destroy` | Prompts for `ploinky-box-<cwd>` | **safety additions:** (1) when the name was inferred, print `targeting '<instance>' (name inferred from the current directory)` before the prompt; (2) when neither the container nor either volume exists, die with `nothing to destroy` instead of pretending to remove things |
| `help` | No identity needed | resolution skipped |

```js
// Like boxRun, but with a controlled working directory — cwd inference tests.
function boxRunIn(cwd, engine, ...args) {
    const r = spawnSync(BOX, args, {
        cwd,
        encoding: 'utf8',
        env: { ...process.env, PLOINKY_BOX_ENGINE: engine },
    });
    return { out: `${r.stdout ?? ''}${r.stderr ?? ''}`, status: r.status };
}

// Fixed-basename child inside a random temp parent: deterministic inference,
// no collision with real containers. Callers clean up the returned parent.
function makeCwd(basename) {
    const parent = fs.mkdtempSync(path.join(os.tmpdir(), 'ploinky-box-cwd-'));
    const dir = path.join(parent, basename);
    fs.mkdirSync(dir);
    return { parent, dir };
}
```

```js
    // (or --name) before any command runs.
    return `${BOX_PREFIX}-${cfg.name}`;
```

Directly below `volumeNames` (after line 110) add:

```js
// Same character class core ploinky uses for workspace-derived container
// names (cli/services/docker/common.js). The 'ploinky-box-' prefix satisfies
// the engine's leading-[a-zA-Z0-9] rule, so only the char class matters here.
export function sanitizeBoxSuffix(raw) {
    return raw.replace(/[^a-zA-Z0-9_.-]/g, '_').slice(0, 63);
}

// Populates cfg.name/cfg.nameSource. Precedence: --name > cwd basename.
// Runs once in main() for every command except help.
export function resolveInstanceIdentity(cfg, cwd = process.cwd()) {
    if (cfg.name) { cfg.nameSource = 'flag'; return cfg; }
    const suffix = sanitizeBoxSuffix(path.basename(cwd));
    if (!/[a-zA-Z0-9]/.test(suffix)) {
        die(`cannot infer an instance name from the current directory (${cwd}); pass --name X`);
    }
    cfg.name = suffix;
    cfg.nameSource = 'cwd';
    return cfg;
}

function inferredNote(cfg) {
    return cfg.nameSource === 'cwd'
        ? ' (name inferred from the current directory; pass --name X to target another instance)'
        : '';
}
```

```js
async function probeRouter(port, attempts = 30) {
    for (let i = 0; i < attempts; i += 1) {
        for (const p of ['status', 'health']) {
            if (await urlOk(`http://127.0.0.1:${port}/${p}`)) return p;
        }
        await sleep(1000);
    }
    return null;
}

// start <agent> [port]: up + in-box `ploinky start <agent> 8080` + router
// probe. [port]/--port choose the HOST side only; the in-box router port is
// always 8080 (the one rule about ports).
async function cmdStart(cfg) {
    const [agent, portArg, ...extra] = cfg.args;
    if (!agent || extra.length > 0) die('usage: ploinky-box start <agent> [port]');
    if (portArg !== undefined) {
        if (!/^\d+$/.test(portArg)) die(`start: host port must be a number, got '${portArg}'`);
        if (cfg.portExplicit && cfg.port !== portArg) {
            die(`start: conflicting host ports (--port ${cfg.port} vs argument ${portArg}); give the port once`);
        }
        cfg.port = portArg;
    }
    await cmdUp(cfg);
    const published = cfg.dryRun ? cfg.port : (hostPort(cfg) || cfg.port);
    if (!cfg.dryRun && published !== cfg.port) {
        process.stderr.write(`ploinky-box: note: existing box publishes host port ${published}; the requested port applies only when the box is created. To change it, run update/recreate with the same flags you used for up plus --port ${cfg.port}.\n`);
    }
    runEngine(cfg, ['exec', '-w', '/workspace', instanceName(cfg), 'ploinky', 'start', agent, '8080']);
    if (cfg.dryRun) return;
    const probePath = await probeRouter(published);
    if (probePath) {
        process.stdout.write(`ploinky-box: router responding on http://127.0.0.1:${published}/${probePath}\n`);
    } else {
        process.stderr.write(`ploinky-box: router did not respond on http://127.0.0.1:${published} within 30s; check: ploinky-box --name ${cfg.name} status\n`);
        process.exitCode = 1;
    }
}
```
