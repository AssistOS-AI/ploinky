# ploinky-box Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the entire Ploinky runtime isolated inside one rootless-podman container (`assistos/ploinky-box`), driven by a dependency-free bash wrapper, so a host needs nothing but podman or docker.

**Architecture:** Two deliverables in two workspace repos. (A) `container-image-builds` gets the image definition: Dockerfile on `quay.io/podman/stable` with Node 24 copied from `node:24-bookworm-slim`, ploinky baked at `/opt/ploinky` from a submodule-pinned checkout, plus a publish workflow and a definition test. (B) `ploinky` gets `container/ploinky-box` (bash wrapper: up/cli/run/cp/status/logs/stop/update/destroy), engine-free wrapper tests via a `--dry-run` seam, a README, and an end-to-end smoke script. Agents run as nested rootless-podman containers inside the box; the box's loopback satisfies every ploinky networking assumption.

**Tech Stack:** bash (macOS 3.2-compatible), Dockerfile, GitHub Actions, node:test (existing `tests/image-definitions.test.mjs` harness), podman/docker CLIs.

**Spec:** `/Users/danielsava/work/file-parser/ploinky/docs/superpowers/specs/2026-07-03-ploinky-box-container-wrapper-design.md` (approved). Read it before starting.

## Global Constraints

- Isolation contract: **never `--privileged`**, never auto-escalate; box runs `--user podman --device /dev/fuse --security-opt seccomp=unconfined` (+ `--security-opt label=disable` only when `getenforce` exists and prints `Enforcing`).
- Commit messages: plain imperative text. **No `Co-Authored-By`, no `Generated by`, no AI/tool attribution of any kind** (workspace policy, applies to both repos).
- Each commit stays scoped to its own repo. In the ploinky repo NEVER stage `node_modules/achillesAgentLib` (a pre-existing submodule pointer change is present; leave it).
- Image identity: `assistos/ploinky-box`, default tag `podman-node24`, platforms `linux/amd64,linux/arm64`, `provenance: false`.
- Ploinky's GitHub default branch is **`master`** (verified via `git ls-remote --symref`); all `source_ref` defaults must be `master`.
- `node --test` (bare, from the container-image-builds root; Node 25 rejects the `tests/` directory-arg form) must pass after every commit to that repo.
- All bash must run under macOS system bash 3.2: no `declare -n`, no associative arrays, guard possibly-empty array expansion as `${ARR[@]+"${ARR[@]}"}` under `set -u`.
- The in-box router port is fixed at 8080 (the wrapper publishes `<host-port>:8080`); in-box `start` commands must use port 8080.
- Absolute repo paths: repo A = `/Users/danielsava/work/file-parser/container-image-builds`, repo B = `/Users/danielsava/work/file-parser/ploinky`.

- [ ] **Step 3: Write the Dockerfile**

Create `/Users/danielsava/work/file-parser/container-image-builds/images/ploinky-box/Dockerfile`:

```dockerfile
ARG PODMAN_BASE=quay.io/podman/stable
ARG NODE_RUNTIME_IMAGE=docker.io/library/node:24-bookworm-slim

FROM ${NODE_RUNTIME_IMAGE} AS node-runtime

FROM ${PODMAN_BASE}

# Node 24 runtime: bookworm glibc binary runs on the newer-glibc Fedora base
# (same multi-stage trick as images/onlyoffice-agent).
COPY --from=node-runtime /usr/local/bin/node /usr/local/bin/node
COPY --from=node-runtime /usr/local/lib/node_modules /usr/local/lib/node_modules
RUN ln -s /usr/local/lib/node_modules/npm/bin/npm-cli.js /usr/local/bin/npm \
    && ln -s /usr/local/lib/node_modules/npm/bin/npx-cli.js /usr/local/bin/npx \
    && dnf install -y git \
    && dnf clean all

# Ploinky baked from the workflow checkout (submodules: true pins achillesAgentLib).
# --ignore-scripts skips the postinstall that would clone achillesAgentLib master
# over the pinned checkout (and would fail: git clone into a non-empty dir errors).
# npm >= 11 prunes packages not listed in package.json, so the pinned submodule
# is parked aside during install and restored afterwards.
COPY sources/ploinky /opt/ploinky
RUN cd /opt/ploinky \
    && mv node_modules/achillesAgentLib /tmp/achillesAgentLib-pinned \
    && npm install --ignore-scripts \
    && mv /tmp/achillesAgentLib-pinned node_modules/achillesAgentLib \
    && test -d node_modules/achillesAgentLib \
    && test -d node_modules/mcp-sdk \
    && rm -rf .git node_modules/achillesAgentLib/.git \
    && mkdir -p /workspace /home/podman/.local/share/containers \
    && chown -R podman:podman /workspace /home/podman/.local/share/containers

ENV PATH=/opt/ploinky/bin:$PATH \
    PLOINKY_WORKSPACE_ROOT=/workspace

COPY images/ploinky-box/entrypoint.sh /usr/local/bin/ploinky-box-entrypoint
RUN chmod 0755 /usr/local/bin/ploinky-box-entrypoint

USER podman
WORKDIR /workspace
ENTRYPOINT ["/usr/local/bin/ploinky-box-entrypoint"]
```

- [ ] **Step 4: Write the entrypoint**

Create `/Users/danielsava/work/file-parser/container-image-builds/images/ploinky-box/entrypoint.sh`:

```bash
#!/usr/bin/env bash
# ploinky-box entrypoint: self-check, then run the given command or idle.
# The self-check is the single source of in-box diagnostics; the wrapper's
# `up` health-wait surfaces these messages verbatim.
set -u

fail() {
    echo "[ploinky-box] SELF-CHECK FAILED: $1" >&2
    exit 1
}

command -v node >/dev/null 2>&1 || fail "node not on PATH"
command -v git >/dev/null 2>&1 || fail "git not on PATH"
command -v podman >/dev/null 2>&1 || fail "podman not on PATH"
[ -x /opt/ploinky/bin/ploinky ] || fail "/opt/ploinky/bin/ploinky missing or not executable"
[ -d /opt/ploinky/node_modules/achillesAgentLib ] || fail "achillesAgentLib missing under /opt/ploinky/node_modules"
[ -w /workspace ] || fail "/workspace not writable (named-volume ownership problem)"
[ -e /dev/fuse ] || fail "/dev/fuse not present - run the box with --device /dev/fuse"
podman info >/dev/null 2>&1 \
    || fail "inner podman not functional - check --security-opt seccomp=unconfined, --device /dev/fuse, and subuid mapping"

echo "[ploinky-box] self-check OK"

if [ "$#" -gt 0 ]; then
    exec "$@"
fi
exec sleep infinity
```

- [ ] **Step 5: Write the publish workflow**

Create `/Users/danielsava/work/file-parser/container-image-builds/.github/workflows/publish-ploinky-box-image.yml`. Note: the blocking Verify step uses `--entrypoint bash` so it asserts file contents deterministically even if the runner cannot run nested podman; the nested check exercises the real entrypoint and is `continue-on-error` per the spec (promote later if stable).

```yaml
name: Publish ploinky-box image

on:
  workflow_dispatch:
    inputs:
      source_ref:
        description: 'AssistOS-AI/ploinky ref to build from'
        required: false
        default: 'master'
        type: string
      image_tag:
        description: 'Docker Hub tag to publish'
        required: false
        default: 'podman-node24'
        type: string

permissions:
  contents: read

concurrency:
  group: publish-ploinky-box-image
  cancel-in-progress: false

env:
  IMAGE_NAME: assistos/ploinky-box
  IMAGE_TAG: ${{ inputs.image_tag || 'podman-node24' }}

jobs:
  publish:
    name: Build and push Docker Hub image
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Checkout ploinky source
        uses: actions/checkout@v4
        with:
          repository: AssistOS-AI/ploinky
          ref: ${{ inputs.source_ref || 'master' }}
          path: sources/ploinky
          submodules: true
          token: ${{ secrets.SOURCE_REPO_TOKEN || github.token }}

      - name: Resolve source revision
        id: source
        run: echo "sha=$(git -C sources/ploinky rev-parse --short=12 HEAD)" >> "$GITHUB_OUTPUT"

      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: assistos
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Build verification image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./images/ploinky-box/Dockerfile
          platforms: linux/amd64
          load: true
          push: false
          tags: ploinky-box:verify

      - name: Verify image contents
        run: |
          docker run --rm --user podman --entrypoint bash \
            --device /dev/fuse --security-opt seccomp=unconfined \
            ploinky-box:verify -lc '
              set -e
              node -v
              git --version
              podman --version
              test -x /opt/ploinky/bin/ploinky
              test -x /opt/ploinky/bin/p-cli
              test -d /opt/ploinky/node_modules/achillesAgentLib
              test -d /opt/ploinky/node_modules/mcp-sdk
              echo IMAGE-OK
            '

      - name: Nested podman check (best effort)
        continue-on-error: true
        run: |
          docker run --rm --user podman \
            --device /dev/fuse --security-opt seccomp=unconfined \
            ploinky-box:verify \
            podman run --rm docker.io/library/alpine echo nested-ok

      - name: Build metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE_NAME }}
          tags: |
            type=raw,value=${{ env.IMAGE_TAG }}
            type=raw,value=${{ env.IMAGE_TAG }}-${{ steps.source.outputs.sha }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./images/ploinky-box/Dockerfile
          platforms: linux/amd64,linux/arm64
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          provenance: false
```

- [ ] **Step 1: Write the failing wrapper tests**

Create `/Users/danielsava/work/file-parser/ploinky/container/wrapper-tests.sh` (mode 0755). These tests need no container engine: they exercise the `--dry-run` seam and assert the isolation contract of the constructed `run` command.

```bash
#!/usr/bin/env bash
# Engine-free tests for the ploinky-box wrapper. Uses --dry-run, which prints
# the engine command instead of executing it, so no podman/docker is needed.
set -u

BOX="$(cd "$(dirname "$0")" && pwd)/ploinky-box"
PASS=0
FAIL=0

check() { # <description> <expected-grep-pattern> <haystack>
    if printf '%s\n' "$3" | grep -qF -- "$2"; then
        PASS=$((PASS + 1)); echo "PASS: $1"
    else
        FAIL=$((FAIL + 1)); echo "FAIL: $1"; echo "  wanted: $2"; echo "  in: $3"
    fi
}

check_absent() { # <description> <forbidden-grep-pattern> <haystack>
    if printf '%s\n' "$3" | grep -qF -- "$2"; then
        FAIL=$((FAIL + 1)); echo "FAIL: $1 (found forbidden '$2')"
    else
        PASS=$((PASS + 1)); echo "PASS: $1"
    fi
}

if bash -n "$BOX"; then
    PASS=$((PASS + 1)); echo "PASS: bash -n syntax check"
else
    FAIL=$((FAIL + 1)); echo "FAIL: bash -n syntax check"
fi

DEFAULT_UP="$(PLOINKY_BOX_ENGINE=podman "$BOX" --dry-run up 2>&1)"
check "default up uses podman"                 "DRY-RUN: podman"                                          "$DEFAULT_UP"
check "default up runs rootless user"          "--user podman"                                            "$DEFAULT_UP"
check "default up passes /dev/fuse"            "--device /dev/fuse"                                       "$DEFAULT_UP"
check "default up unconfines seccomp"          "seccomp=unconfined"                                       "$DEFAULT_UP"
check "default up publishes loopback 8080"     "127.0.0.1:8080:8080"                                      "$DEFAULT_UP"
check "default up mounts workspace volume"     "ploinky-box-workspace:/workspace"                         "$DEFAULT_UP"
check "default up mounts containers volume"    "ploinky-box-containers:/home/podman/.local/share/containers" "$DEFAULT_UP"
check "default up uses default image"          "docker.io/assistos/ploinky-box:podman-node24"             "$DEFAULT_UP"
check "default up reaps zombies"               "--init"                                                   "$DEFAULT_UP"
check_absent "no --privileged, ever"           "--privileged"                                             "$DEFAULT_UP"

NAMED_UP="$(PLOINKY_BOX_ENGINE=docker "$BOX" --dry-run --name qa --port 9090 --listen-lan up 2>&1)"
check "named up uses docker when forced"       "DRY-RUN: docker"                                          "$NAMED_UP"
check "named up names the instance"            "--name ploinky-box-qa"                                    "$NAMED_UP"
check "named up prefixes volumes"              "ploinky-box-qa-workspace:/workspace"                      "$NAMED_UP"
check "lan flag binds all interfaces"          "0.0.0.0:9090:8080"                                        "$NAMED_UP"
check_absent "named up still not privileged"   "--privileged"                                             "$NAMED_UP"

IMG_UP="$(PLOINKY_BOX_ENGINE=podman "$BOX" --dry-run --image example.org/x/y:z up 2>&1)"
check "image override respected"               "example.org/x/y:z"                                        "$IMG_UP"

RUN_OUT="$(PLOINKY_BOX_ENGINE=podman "$BOX" --dry-run run start demo 8080 2>&1)"
check "run passes through to ploinky"          "exec -w /workspace ploinky-box ploinky start demo 8080"   "$RUN_OUT"

CP_OUT="$(PLOINKY_BOX_ENGINE=podman "$BOX" --dry-run cp /tmp/f box:/workspace/f 2>&1)"
check "cp maps box: prefix to instance"        "cp /tmp/f ploinky-box:/workspace/f"                       "$CP_OUT"

echo
echo "wrapper-tests: $PASS passed, $FAIL failed"
[ "$FAIL" -eq 0 ]
```

# ploinky-box: run the Ploinky runtime isolated inside a rootless-podman container.
# Host requirements: podman (preferred) or docker. Nothing else.
# Isolation contract: never --privileged; explicit crossings only (published
# router port, `cp`, opt-in --mount).
set -euo pipefail

DEFAULT_IMAGE="docker.io/assistos/ploinky-box:podman-node24"
BOX_PREFIX="ploinky-box"

ENGINE="${PLOINKY_BOX_ENGINE:-}"
NAME=""
PORT="8080"
IMAGE="$DEFAULT_IMAGE"
MOUNT_DIR=""
LISTEN_LAN=0
DRY_RUN=0

usage() {
    cat <<'EOF'
ploinky-box - run Ploinky isolated in a rootless-podman container

Usage: ploinky-box [flags] <command> [args]

Commands:
  up         Create/start the box (pulls the image on first use)
  cli        Interactive Ploinky console (p-cli) inside the box
  run <...>  One-shot ploinky command, e.g.: ploinky-box run start demo 8080
  cp A B     Copy in/out; prefix the container side with box:
             e.g. ploinky-box cp ./file box:/workspace/file
  status     Container state + router probe
  logs       Show recent .ploinky logs from the box
  stop       Stop the box (volumes kept)
  update     Pull a newer image and recreate the box (volumes kept);
             pass the same flags you used with up
  destroy    Remove the box AND its volumes (asks for confirmation)

Flags:
  --name X       Extra isolated instance (container ploinky-box-X)
  --port N       Host port for the router (default 8080).
                 Inside the box, always start the router on port 8080.
  --image I      Image override (default docker.io/assistos/ploinky-box:podman-node24)
  --mount DIR    Bind DIR read-write at /workspace/mounted (pierces isolation)
  --listen-lan   Publish the router on 0.0.0.0 instead of 127.0.0.1
  --engine E     podman|docker (default: auto-detect, podman first)
  --dry-run      Print the engine command for up/run/cp instead of executing
  -h, --help     This help
EOF
}

die() { echo "ploinky-box: $*" >&2; exit 1; }

COMMAND=""
ARGS=()
while [ $# -gt 0 ]; do
    case "$1" in
        --name)   NAME="${2:?--name needs a value}"; shift 2 ;;
        --port)   PORT="${2:?--port needs a value}"; shift 2 ;;
        --image)  IMAGE="${2:?--image needs a value}"; shift 2 ;;
        --mount)  MOUNT_DIR="${2:?--mount needs a value}"; shift 2 ;;
        --engine) ENGINE="${2:?--engine needs a value}"; shift 2 ;;
        --listen-lan) LISTEN_LAN=1; shift ;;
        --dry-run)    DRY_RUN=1; shift ;;
        -h|--help) usage; exit 0 ;;
        *)
            if [ -z "$COMMAND" ]; then
                COMMAND="$1"; shift
            else
                ARGS+=("$1"); shift
            fi
            ;;
    esac
done
[ -n "$COMMAND" ] || { usage; exit 1; }

INSTANCE="$BOX_PREFIX${NAME:+-$NAME}"
VOL_WS="${INSTANCE}-workspace"
VOL_CT="${INSTANCE}-containers"

detect_engine() {
    if [ -n "$ENGINE" ]; then
        # In --dry-run the binary need not exist: tests force both engine names
        # on machines that may have only one (or neither) installed.
        if [ "$DRY_RUN" -eq 0 ]; then
            command -v "$ENGINE" >/dev/null 2>&1 || die "requested engine '$ENGINE' not found in PATH"
        fi
        return 0
    fi
    local c
    for c in podman docker; do
        if command -v "$c" >/dev/null 2>&1; then ENGINE="$c"; return 0; fi
    done
    die "neither podman nor docker found in PATH. Install podman (https://podman.io) or docker."
}

preflight() {
    [ "$DRY_RUN" -eq 1 ] && return 0
    if [ "$ENGINE" = "podman" ] && [ "$(uname -s)" = "Darwin" ]; then
        podman machine inspect --format '{{.State}}' 2>/dev/null | grep -q running \
            || die "podman machine is not running. Start it with: podman machine start"
    fi
    if [ "$ENGINE" = "docker" ]; then
        docker info >/dev/null 2>&1 \
            || die "docker daemon unreachable. Start Docker Desktop (macOS) or dockerd (Linux)."
    fi
}

engine() {
    if [ "$DRY_RUN" -eq 1 ]; then
        printf 'DRY-RUN: %s' "$ENGINE"
        printf ' %s' "$@"
        printf '\n'
    else
        "$ENGINE" "$@"
    fi
}

selinux_enforcing() {
    command -v getenforce >/dev/null 2>&1 && [ "$(getenforce 2>/dev/null)" = "Enforcing" ]
}

box_exists()  { "$ENGINE" container inspect "$INSTANCE" >/dev/null 2>&1; }
box_running() { [ "$("$ENGINE" container inspect --format '{{.State.Status}}' "$INSTANCE" 2>/dev/null || true)" = "running" ]; }

host_port() {
    "$ENGINE" port "$INSTANCE" 8080/tcp 2>/dev/null | head -n 1 | awk -F: '{print $NF}'
}

build_run_args() {
    local bind_ip="127.0.0.1"
    [ "$LISTEN_LAN" -eq 1 ] && bind_ip="0.0.0.0"
    RUN_ARGS=(run -d --init --name "$INSTANCE"
        --user podman
        --device /dev/fuse
        --security-opt seccomp=unconfined
        -p "${bind_ip}:${PORT}:8080"
        -v "${VOL_WS}:/workspace"
        -v "${VOL_CT}:/home/podman/.local/share/containers"
        -e PLOINKY_WORKSPACE_ROOT=/workspace
    )
    if selinux_enforcing; then
        RUN_ARGS+=(--security-opt label=disable)
    fi
    if [ -n "$MOUNT_DIR" ]; then
        [ -d "$MOUNT_DIR" ] || die "--mount directory not found: $MOUNT_DIR"
        RUN_ARGS+=(-v "$(cd "$MOUNT_DIR" && pwd):/workspace/mounted")
        echo "ploinky-box: WARNING: --mount pierces the isolation boundary for $MOUNT_DIR" >&2
    fi
    RUN_ARGS+=("$IMAGE")
}

ensure_image() {
    [ "$DRY_RUN" -eq 1 ] && return 0
    "$ENGINE" image inspect "$IMAGE" >/dev/null 2>&1 && return 0
    "$ENGINE" pull "$IMAGE" || die "cannot pull $IMAGE.
  - Publish it: gh workflow run publish-ploinky-box-image.yml --repo AssistOS-AI/container-image-builds
  - Or point at another image with --image"
}

wait_healthy() {
    [ "$DRY_RUN" -eq 1 ] && return 0
    local i state
    for i in $(seq 1 30); do
        state="$("$ENGINE" container inspect --format '{{.State.Status}}' "$INSTANCE" 2>/dev/null || echo missing)"
        if [ "$state" = "running" ] && "$ENGINE" logs "$INSTANCE" 2>&1 | grep -q "self-check OK"; then
            echo "ploinky-box: '$INSTANCE' is up (router will publish on port $PORT once started inside)."
            return 0
        fi
        if [ "$state" = "exited" ]; then
            echo "ploinky-box: '$INSTANCE' failed its self-check:" >&2
            "$ENGINE" logs "$INSTANCE" >&2 2>&1 || true
            die "fix the reported cause; do NOT fall back to --privileged"
        fi
        sleep 1
    done
    die "'$INSTANCE' did not become healthy within 30s; inspect with: $ENGINE logs $INSTANCE"
}

cmd_up() {
    preflight
    if [ "$DRY_RUN" -eq 0 ] && box_running; then
        echo "ploinky-box: '$INSTANCE' already running."
        return 0
    fi
    if [ "$DRY_RUN" -eq 0 ] && box_exists; then
        engine start "$INSTANCE" >/dev/null
    else
        if [ "$DRY_RUN" -eq 0 ] && (exec 3<>"/dev/tcp/127.0.0.1/${PORT}") 2>/dev/null; then
            die "host port ${PORT} is already in use; choose another with --port"
        fi
        ensure_image
        build_run_args
        engine "${RUN_ARGS[@]}"
    fi
    wait_healthy
}

require_running() {
    [ "$DRY_RUN" -eq 1 ] && return 0
    box_running || die "'$INSTANCE' is not running. Start it with: ploinky-box${NAME:+ --name $NAME} up"
}

cmd_cli() {
    preflight
    require_running
    engine exec -it -w /workspace "$INSTANCE" p-cli
}

cmd_run() {
    preflight
    require_running
    engine exec -w /workspace "$INSTANCE" ploinky ${ARGS[@]+"${ARGS[@]}"}
}

cmd_cp() {
    preflight
    require_running
    [ "${#ARGS[@]}" -eq 2 ] || die "usage: ploinky-box cp <src> <dst>  (prefix the container side with box:)"
    local src="${ARGS[0]}" dst="${ARGS[1]}"
    case "$src$dst" in
        *box:*) : ;;
        *) die "one side must carry the box: prefix, e.g. box:/workspace/file" ;;
    esac
    src="${src/#box:/$INSTANCE:}"
    dst="${dst/#box:/$INSTANCE:}"
    engine cp "$src" "$dst"
}

cmd_status() {
    preflight
    if ! box_exists; then echo "ploinky-box: '$INSTANCE' does not exist."; return 1; fi
    echo "container: $INSTANCE ($("$ENGINE" container inspect --format '{{.State.Status}}' "$INSTANCE"))"
    local hp
    hp="$(host_port)"
    if [ -n "$hp" ] && curl -sf -o /dev/null "http://127.0.0.1:${hp}/status"; then
        echo "router:    responding on http://127.0.0.1:${hp}/status"
    elif [ -n "$hp" ] && curl -sf -o /dev/null "http://127.0.0.1:${hp}/health"; then
        echo "router:    responding on http://127.0.0.1:${hp}/health"
    else
        echo "router:    not responding (start it inside: ploinky-box${NAME:+ --name $NAME} run start <agent> 8080)"
    fi
}

cmd_logs() {
    preflight
    require_running
    engine exec "$INSTANCE" sh -lc 'tail -n 100 /workspace/.ploinky/logs/*.log 2>/dev/null || echo "no .ploinky logs yet"'
}

cmd_stop() {
    preflight
    box_exists || { echo "ploinky-box: '$INSTANCE' does not exist."; return 0; }
    engine stop "$INSTANCE" >/dev/null && echo "ploinky-box: '$INSTANCE' stopped (volumes kept)."
}

cmd_update() {
    preflight
    engine pull "$IMAGE"
    if box_exists; then
        engine stop "$INSTANCE" >/dev/null 2>&1 || true
        engine rm "$INSTANCE" >/dev/null
    fi
    build_run_args
    engine "${RUN_ARGS[@]}"
    wait_healthy
    echo "ploinky-box: updated. Resume agents with: ploinky-box${NAME:+ --name $NAME} run start"
}

cmd_destroy() {
    preflight
    if [ "$DRY_RUN" -eq 0 ]; then
        printf "Remove container '%s' and volumes '%s' + '%s'? [y/N] " "$INSTANCE" "$VOL_WS" "$VOL_CT"
        read -r reply
        case "$reply" in y|Y) : ;; *) die "aborted" ;; esac
    fi
    engine stop "$INSTANCE" >/dev/null 2>&1 || true
    engine rm "$INSTANCE" >/dev/null 2>&1 || true
    engine volume rm "$VOL_WS" "$VOL_CT" >/dev/null 2>&1 || true
    echo "ploinky-box: '$INSTANCE' and its volumes removed."
}

detect_engine
case "$COMMAND" in
    up)      cmd_up ;;
    cli)     cmd_cli ;;
    run)     cmd_run ;;
    cp)      cmd_cp ;;
    status)  cmd_status ;;
    logs)    cmd_logs ;;
    stop)    cmd_stop ;;
    update)  cmd_update ;;
    destroy) cmd_destroy ;;
    help)    usage ;;
    *) die "unknown command '$COMMAND' (see: ploinky-box --help)" ;;
esac
```

# ploinky-box

Run the entire Ploinky runtime isolated inside one rootless-podman container.
The host needs nothing but podman (preferred) or docker — no node, no git, no
ploinky checkout. Agents run as nested containers *inside* the box; nothing
they do touches the host filesystem.

## Quick start

    curl -fsSL https://raw.githubusercontent.com/AssistOS-AI/ploinky/master/container/ploinky-box -o ploinky-box
    chmod +x ploinky-box
    ./ploinky-box up
    ./ploinky-box cli          # interactive Ploinky console
    # inside: enable agent demo
    # inside: start demo 8080
    open http://127.0.0.1:8080/status

## The one rule about ports

The wrapper publishes host port `--port N` (default 8080) to **container port
8080**. Inside the box, always start the router on 8080:
`start <agent> 8080`. Any other in-box port is unreachable from the host.

## Commands

| Command | Effect |
| --- | --- |
| `up` | Create/start the box; pulls the image on first use |
| `cli` | Interactive `p-cli` console inside the box |
| `run <args>` | One-shot ploinky command (`run start demo 8080`, `run list agents`) |
| `cp A B` | Copy in/out; container side uses the `box:` prefix |
| `status` | Container state + router probe |
| `logs` | Recent `.ploinky` logs |
| `stop` | Stop the box; workspace and agent images survive |
| `update` | Pull newer image, recreate the box (pass the same flags as `up`) |
| `destroy` | Remove the box AND its volumes (asks first) |

Flags: `--name X` (extra isolated instance), `--port N`, `--image I`,
`--mount DIR`, `--listen-lan`, `--engine podman|docker`, `--dry-run`.
`PLOINKY_BOX_ENGINE` overrides engine detection.

## Isolation contract

The box runs **without `--privileged`**: `--user podman --device /dev/fuse
--security-opt seccomp=unconfined` (plus `label=disable` on SELinux-enforcing
hosts). The only crossings of the boundary are: the published router port
(loopback-only unless `--listen-lan`), explicit `cp`, and the opt-in `--mount DIR`
(bind-mounted read-write at `/workspace/mounted` — you are piercing the sandbox).
State lives in two named volumes per instance: `<instance>-workspace`
(the Ploinky workspace) and `<instance>-containers` (nested agent images).
`stop`/`update` keep them; only `destroy` deletes them.

## Limitations

- In-box `ploinky update` cannot update the baked runtime (read-only,
  `.git` stripped); update the box itself with `ploinky-box update`.
- `additionalServerPort` in `container` mode relies on inspect-derived
  container IPs, which rootless podman does not expose; use `host` mode for
  such agents. (Smoke-test outcome recorded below.)
- Agents with `lite-sandbox: true` (bwrap/seatbelt) are unsupported inside
  the box in v1.
- On macOS, `--mount` directories must live under the podman-machine /
  Docker Desktop file share (default: your home directory).
- Windows hosts are unsupported.

#!/usr/bin/env bash
# End-to-end smoke for ploinky-box. Needs a container engine and either the
# published image or SMOKE_IMAGE pointing at a local build (e.g. ploinky-box:dev).
# Usage: [SMOKE_IMAGE=...] [SMOKE_PORT=...] [SMOKE_AGENT=...] bash smoke-box.sh
set -u

BOX="$(cd "$(dirname "$0")" && pwd)/ploinky-box"
NAME="smoke$$"
PORT="${SMOKE_PORT:-8090}"
IMAGE="${SMOKE_IMAGE:-docker.io/assistos/ploinky-box:podman-node24}"
AGENT="${SMOKE_AGENT:-demo}"
FAILED=0
TMP_IN="$(mktemp)"
TMP_OUT="$(mktemp)"

step() { # <description> <command...>
    local desc="$1"; shift
    if "$@"; then
        echo "PASS: $desc"
    else
        echo "FAIL: $desc"
        FAILED=1
    fi
}

probe_router() {
    local i
    for i in $(seq 1 30); do
        if curl -sf -o /dev/null "http://127.0.0.1:${PORT}/status" \
           || curl -sf -o /dev/null "http://127.0.0.1:${PORT}/health"; then
            return 0
        fi
        sleep 1
    done
    return 1
}

echo "== ploinky-box smoke: instance=$NAME port=$PORT image=$IMAGE agent=$AGENT =="

step "up"                    "$BOX" --name "$NAME" --port "$PORT" --image "$IMAGE" up
step "enable agent"          "$BOX" --name "$NAME" run enable agent "$AGENT"
step "start agent + router"  "$BOX" --name "$NAME" run start "$AGENT" 8080
step "router responds"       probe_router

echo "smoke payload" > "$TMP_IN"
step "cp into box"           "$BOX" --name "$NAME" cp "$TMP_IN" box:/workspace/smoke.txt
step "cp out of box"         "$BOX" --name "$NAME" cp box:/workspace/smoke.txt "$TMP_OUT"
step "cp round-trip intact"  diff "$TMP_IN" "$TMP_OUT"

step "stop"                  "$BOX" --name "$NAME" stop
step "re-up (state kept)"    "$BOX" --name "$NAME" --port "$PORT" --image "$IMAGE" up
step "resume agents"         "$BOX" --name "$NAME" run start
step "router responds again" probe_router

if [ -n "${SMOKE_WS_AGENT:-}" ]; then
    step "ws agent enable"   "$BOX" --name "$NAME" run enable agent "$SMOKE_WS_AGENT"
    step "ws agent restart"  "$BOX" --name "$NAME" run start
    echo "NOTE: verify the additionalServerPort surface of $SMOKE_WS_AGENT manually via the router, then record the outcome in container/README.md"
else
    echo "WS-CHECK SKIPPED (set SMOKE_WS_AGENT=<agent-with-additionalServerPort> to exercise it)"
fi

printf 'y\n' | "$BOX" --name "$NAME" destroy
rm -f "$TMP_IN" "$TMP_OUT"

echo
if [ "$FAILED" -eq 0 ]; then
    echo "== SMOKE PASSED =="
else
    echo "== SMOKE FAILED =="
fi
exit "$FAILED"
```

## Risks the implementer must not paper over

- **Nested rootless podman is the load-bearing bet** (Task 2 Step 4 / Task 5). If it fails on a platform, the recorded fallback is inner `storage.conf` with `driver = "vfs"` — never `--privileged`.
- **Agent default image pull happens inside the box** — slow first start is expected, not a hang; `logs` shows progress.
- **`npm install --ignore-scripts`** is deliberate (spec §3.1); if some dependency turns out to need its scripts, surface it — do not silently re-enable scripts.
- **Deps caches**: ploinky prepares agent node_modules in short-lived install containers (README.md "Dependency caches"), so the box needs no build toolchain; if smoke shows otherwise, extend the image via `dnf` in Task 1's Dockerfile and update the definition test.
