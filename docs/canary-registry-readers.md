# Canary registry readers

A rollout adds a physical runtime to `.ploinky/agents.json`. The route still names its primary in `container`. Its `canary.container` names a second registry record, whose `canaryOf` points back to the route key. Presence of the marker is enough to exclude a record from ordinary lifecycle work, even when its value is malformed. Generation compilation validates the link in both directions.

The tables use repository-relative paths and source line numbers. **Skip** excludes the record from logical-agent selection or refuses an explicit canary target. **Include** retains the physical record for the operation shown. **Tuple-match** requires the particular runtime identity described in that row.
