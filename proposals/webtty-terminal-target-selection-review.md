## 2. Executive verdict

**Approve with changes.**

The proposal is unusually well grounded: its fail-closed posture, exact-identity model, revalidation-at-create rule, and refusal to trust manifest declarations all match mechanisms that already exist in this codebase (`confinement.js` ownership verification, `edgeRoutePlan.exactAgentRuntime`, relay mount verification). Its "Verified current state" table survived spot-checking with one substantive exception. No P0 was found and no architectural rework is needed.

Two P1 defects must be fixed in the design before implementation: (1) the proposal never reconciles the agent provider with the current **feature-wide** unproven-cleanup disable, so one ambiguous agent-shell cleanup would 503 Box terminals too — contradicting the proposal's own acceptance row; and (2) the agent-PTY candidate table is missing the decisive environmental fact — nested rootless Podman runs agent processes **inside the Box's PID namespace**, so the existing `/proc` identity/termination machinery can prove and reap in-container shells directly — which inverts the recommended investigation order (the engine REST API would require a new long-lived `podman system service` daemon and is the weaker first candidate here).

Five P2 corrections tighten the source-of-truth, eligibility, path-translation, token, and provider-integration designs; four P3 notes cover transport wording, discovery latency, Explorer client details, and sequencing.

### P1-2 — The agent-PTY candidate table is missing the decisive fact (Box PID-namespace visibility) and recommends the weakest-fit candidate first

| Field | Content |
| --- | --- |
| Claim | §10 ranks "Podman engine exec API" as "Investigate first". Candidate 3 (agent-side broker) stays rejected (UR-8: would need a PTY runtime in every image). Candidate 4 (runtime relay) stays rejected as-is — but note the relay's *confinement pattern* (not its transport) is the template for target verification. |
| Verification | Phase-0 spike exit evidence must include, in a real Box: marker-based Box-side discovery of the exec'd shell; start-token identity stability; resize propagation through the nested PTY pair (node-pty resize → SIGWINCH → client → conmon); client-kill leaves the shell running (proves the cleanup protocol is necessary); verified group-kill reaps a foreground child; NSpid-based in-container kill for a non-root-USER image; `ExecIDs` empty after close; `podman rm -f`/`stop` of the container terminates the exec session (workspace-destroy path). |

### P3-1 — The streaming transport is SSE + POST, not WebSocket; the proposal (and the review brief) must name the real seams

### P3-2 — Discovery must use the async runtime collectors and bound its cost

## 5. Recommended architecture

End-to-end flow with the corrections applied:

| Step | Behavior |
| --- | --- |
| 1. Menu action | Explorer opens the chooser modal and calls `GET /webtty/targets?dir=<relative>` (admin + availability + route binding enforced as on every `/webtty` route). |
| 2. Resolve | Router (single process, in-Box) loads the **active** edge generation's agents map; for each identity-complete record (`exactAgentRuntime` pattern), async-inspects the immutable `containerId` (bounded concurrency/timeout); verifies `Running` + `verifyInspectedContainer` labels; runs the P2-3 mount algorithm against the canonical selected realpath; derives access from post-shadow `RW`. Box target always first. Failures omit the target. |
| 3. Mint | One launch record per offered target: random id, Router memory, bound to admin lease fingerprint + host/generation binding + canonical dir + identity tuple; TTL 2–5 min; quota-bounded; wiped on generation change/restart. Response rows: `{id, kind, label, detail, access, cwdDisplay}` — no container IDs, host paths, or env. |
| 4. Handoff | Row click (its own user gesture) opens `/webtty/#launch=<id>` via `window.open`. The page strips the fragment (`history.replaceState`) and POSTs `{launch, cols, rows}`. |
| 5. Create | Handler: admin → availability → mutation proof → consume record (single-use; owner/dir/generation match) → **re-resolve from scratch** (same inspection + mount algorithm against the same immutable `containerId`; any drift → 409-class stale-target error that sends the browser back to the chooser) → commit generation → provider start. |
| 6. Box provider | Unchanged worker (`terminal-worker.mjs`). |
| 7. Agent provider | New `agent-terminal-worker.mjs`: node-pty spawns `podman exec -it -w <translatedCwd> -e TERM=… <containerId> /bin/bash --noprofile --norc` (controlled `/bin/sh` retry on exec-start failure); discovers the in-container shell in Box `/proc` by random marker; captures `linux-proc` start-token identity of both the client and the shell; reports both through a protocol-v2 `ready`. |
| 8. Records | v2 recovery records with `target` discriminator; agent records carry `containerId` + client + shell identities; recovery treats container-absent + shell-identity-gone as provably reclaimed. |
| 9. Close/cleanup | Close the client PTY; verify shell exit via `/proc` identity; escalate TERM→KILL on the verified group (same-UID) or via one-shot in-container `kill` using `NSpid` (cross-UID); post-close: shell identity gone + `podman inspect '{{.ExecIDs}}'` drained. Ambiguity → close + quarantine **that target only** (P1-1). |
| 10. Invalidation | Existing 5s `validateLiveSessions` sweep (route lease, auth lease, timeouts) applies unchanged; agent sessions add a low-frequency container-identity recheck, and container stop/removal ends the shell immediately anyway (client EOF), with replacement-attach impossible because exec addresses the immutable ID. |
| 11. Audit | Existing lifecycle audit plus `{targetKind, hashed instance identity, generation, access, cleanup reason}` — no contents, no env. |

## 6. Better alternative

There is **no materially better overall architecture**; the proposal's shape is right once the P1/P2 corrections land. The one considered alternative — a WebTTY-owned chooser page (open `/webtty/?dir=…` exactly as today; the page itself lists targets and creates the session on an explicit row click) — is *simpler*: it deletes the launch-record handoff entirely (selection travels inside an ordinary same-origin authenticated POST), reduces Explorer's change to near zero, makes stale-refresh a same-page loop, and incidentally converts the auto-create-on-load behavior into an explicit user action for agent targets (removing the P2-4 forged-link concern by construction). It is not recommended as primary because requirement 1 asks for the chooser in the Explorer flow and the Explorer modal is safe with P2-4 applied — but it should be recorded in the plan as the sanctioned fallback if the modal's handoff or popup behavior misbehaves in real browsers, and the server contract above supports both without change.
