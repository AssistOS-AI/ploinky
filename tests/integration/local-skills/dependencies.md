# Acceptance harness dependencies

The harness adds no third-party JavaScript packages, vendored code, Python, build step, or test framework. New executable files are `.mjs` modules using Node built-ins. The candidate repositories are explicit systems under test, not bundled libraries. No source or runtime package is installed by the harness.

| Requirement | Scope and resolution | Decision and maintenance |
| --- | --- | --- |
| Node.js 22 or later | Required runtime; invoked through `node` and `process.execPath`. Use an environment-provided Node runtime, optionally through a separately pinned Linux image. | Node's built-in runner, assertions, processes, and filesystem APIs cover the harness; an external test framework is unnecessary. Use a compatible environment-provided runtime. No runtime is redistributed here. |
| Four source candidates | Required via `SKILLS_TEST_ACHILLES`, `SKILLS_TEST_ALA`, `SKILLS_TEST_PLOINKY`, and `SKILLS_TEST_EXPLORER`. Record exact source commits in the deployment candidate manifest. | Real cross-repository imports are necessary to detect integration failures. Replacing them with copied logic would weaken the test. No implicit home-relative or sibling-checkout lookup is used by the harness. The runner validates absolute paths and manifests; imports then require the candidate interfaces documented in the README. Existing source dependencies and licenses remain governed by each repository. |
| Linux `/proc` process identity | Required by the real RobotStore lock implementation. Non-Linux execution fails before fixture creation. | Linux semantics cannot be replaced with a portable lock mock without weakening this test. Use an existing Linux host, VM, or container. |
| Podman and existing Linux images | Optional development environment for macOS. Record the exact engine version and immutable image reference in deployment evidence. | A native Linux host removes this dependency. The image tags are not immutable reproducibility pins; retain the recorded results and resolve/pin the image identity for a release gate. These tools/images are not included in this artifact. Their full transitive inventory and license review were not performed here. |
| Bubblewrap, real Codex executable, ALA's existing AgentLib dependency, and provider connectivity | Optional, required only by `--native`. Bubblewrap is located by ALA's existing resolver and tested for private `/proc`. `CODEX_BIN` must be absolute and executable. AgentLib resolution follows the candidate's existing installation logic; provision it as required by that repository. | Required to test real native registration and execution; the deterministic consumer deliberately does not claim equivalence. Reuse a supported provisioned environment. Missing capabilities fail explicitly before native model work; no downloads or installations occur. Versions and licenses belong to the selected existing installation and are not bundled or newly approved by this test. |
| Dedicated authentication home | Optional, required only by `--native`, supplied through `SKILLS_TEST_NATIVE_HOME`. Only `.codex/auth.json` is copied into a temporary private home. | Needed for authenticated model work. The test checks readability, sets the copy to mode `0600`, and cleans up the fixture. Credentials are not committed or included in the artifact. |

No dependency licenses or notices are bundled because no external source or binary is redistributed. Source, installation, and update instructions for the systems under test remain in their own repositories. Provision missing environment tools separately through the user's approved environment workflow; the harness itself intentionally has no installer. Unknown environment component licenses/versions are not asserted as verified facts.
