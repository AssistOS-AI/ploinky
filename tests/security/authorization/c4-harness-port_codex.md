# C4 guarded harness port

The guarded harness requires an administrator-created, run-owned open team room before room-list and workspace-feed controls. Entitled listings must contain that room. The lesser authenticated user must receive exactly `rooms: []` and `canManageRooms: false`; anonymous access and lesser-user workspace-feed access require explicit authorization denial.

Each entitled feed positive decodes workspace events and requires a `meeting.created` event whose workspace, meeting ID, room ID, projected meeting ID and run-scoped name match the visible owned fixture. Empty feeds, malformed events and unrelated events fail. Fixture/control failures fail checks instead of becoming reviewed gaps. Cleanup checks the exact room ID and run name before deletion.

Before creating the fixture, the harness verifies that the random run name is absent from the administrator directory and records baseline room IDs. It arms cleanup before dispatching creation. A lost response is reconciled only through one exact-name match with a new authoritative ID, then a matching room read. Missing, ambiguous, preexisting or unreadable identities fail cleanup without deleting a guessed room. Deletion requires `{ ok: true, deleted: true, roomId: ownedRoomId }` and a subsequent guarded get that returns the exact `Meeting not found.` tool failure or its production SDK wrapper `MCP error -32603: Meeting not found.`. Authentication, initialization, HTTP and transport failures do not establish absence.

The mandatory definition now has 501 live checks and 10 offline checks, adding one fixture check and five feed actor checks to the prior 495 live definitions. Both room-list and feed administrator positives depend on the successful fixture; actor controls depend on their administrator positive. The policy digest is generated by `node tests/security/authorization/acceptance/digest.mjs`; external frozen pins are not edited by this port.

## Remaining integration gates

- Regenerate `agent-inventory.mjs` with `inventory-generate.mjs` from the final pinned integrated source checkouts, authoritative preflight and runtime summary. The existing generated inventory is deliberately unchanged and does not describe final C4 source revisions or listing policy.
- Re-derive runtime and gap inputs when integrated source contracts change, regenerate mandatory definitions, and compute the policy digest from those final bytes.
- Obtain independent review of the exact harness candidate and final acceptance files; root reviews the final inventory, digest and pins before live work.
- Retain final ownership, cleanup, strict typed gaps and raw exit/verdict evidence in the authorized guarded A7 run. Offline synthetic checks do not establish live acceptance or release readiness.
